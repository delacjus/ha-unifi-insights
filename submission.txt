## Description

🚨 Severity: CRITICAL
💡 Vulnerability: The Carrier Fabric setup flow uses the API key string directly in `hashlib.sha256()` to generate the `unique_id` of the config entry. If the first 16 bytes of the generated hash are logged or stored in diagnostics, the raw key becomes a target for offline dictionary attacks or rainbow table generation.
🎯 Impact: An attacker with access to Home Assistant logs or `.storage/core.config_entries` could potentially recover the raw API key for the Carrier Fabric service if it is weak, exposing the customer’s ISP network logic.
🔧 Fix: Used `hmac.new` with a salt (`unifi_insights_carrier_key`) to derive the key hash, rather than directly hashing the secret key.
✅ Verification: Ensure the updated `test_carrier_fabric_config_flow.py` passes using `pytest tests/test_carrier_fabric_config_flow.py`.

Sentinel: Ensuring cryptographic best practices across Home Assistant config flows. 🛡️
